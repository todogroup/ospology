# 簡介

## 本指南的目的與讀者

對參與開放原始碼的人而言，無法說服企業內其他單位投入更多心力，往往令人挫折。開源倡議者知道，企業正錯失創造商業價值的機會，卻常常找不到適切的論點來爭取公司其他成員的認同。根據 [Linux Foundation](https://www.linuxfoundation.org/hubfs/Research%20Reports/2025GlobalSpotlight_Oct-27-2025%20V4.pdf?hsLang=en) 於 2025 年進行的研究，僅有 36% 的組織訂有正式的開放原始碼策略，正反映了這項困境。

本指南的目標，是提供開源倡議者所需的論點，讓他們與不熟悉開放原始碼或對其有所誤解的企業成員討論企業如何從中創造價值時，能有更具成效的對話。

本指南主要探討的效益，不只是被動使用開放原始碼軟體，還包括積極成為開源社群的一員，或將內部軟體專案以開放原始碼專案形式發布。在多數組織中，匿名使用開源軟體通常不具爭議；無論企業利害關係人是否知道，所有組織其實都在使用。開放原始碼在商業世界中無所不在，企業領導者應該了解並接受這項事實。至少，組織必須掌握自身使用開源軟體的情況，因為其中仍有相關風險。因此，備妥軟體物料清單（SBOM）並履行授權條款要求，對避免法律風險十分重要。

然而，當組織積極參與開源生態系，包括成為開源社群的活躍成員，以及建立並維護自己的專案與社群後，便有機會將貢獻納入商業策略，例如與開源生態系建立真正的策略關係。

不過，在繼續討論前必須留意：開放原始碼中的維護者、使用者與貢獻者都是個人。組織可以擁有儲存庫、商標與著作權，但對開放原始碼專案的貢獻仍必須由個人提出。撰寫及提交程式碼、提出議題、送出 Pull Request，以及核准 Pull Request 的都是個人。組織聘用曾參與開源工作的人才時，也會受益於該員工多年來在開源社群累積的聲譽。反過來說，參與專案的員工離開組織時，也會帶走自己建立的聲譽，甚至可能一併帶走專案的提交權限與維護者身分。若組織只是下載並使用開源專案，這點通常影響不大；但開始制定開放原始碼策略後，了解並管理這種情況可能就會變得至關重要。
